# Upgrade kit

This project was created by `vibe create` from the Vibe starter kit. `.vibe-kit.json` records the kit repository, branch and the commit the project currently matches. Syncing is recurring; `vibe upgrade` does the git mechanics, you resolve.

Adapted from kriasoft React Starter Kit's `merge-seed` skill (MIT).

## Core rule

**Upstream owns mechanism. This project owns identity and scope.**

Adopt from upstream: dependency and toolchain versions, build and config structure, framework API updates, security fixes, refactors, newly required env variables, generators (`packages/cli`), shared packages.

Keep local: product name, copy and positioning; generated panels (`apps/app/src/lib/panels/*.config.ts`), resources and models; `IDENTITY_PROFILE` and project-only env; migrations already in history; deliberate additions and deletions.

When a hunk mixes both, take upstream's structure and reapply local values. **Never take a whole side merely to clear a conflict.** `AGENTS.md`, `docs/` and the current code on `main` define local identity and scope.

## Merge

Prerequisites: the project is a git repository with a clean tree on `main` (first time: `git init && git add -A && git commit -m "chore: initial import"`).

```bash
git status --short                                              # must be clean
pnpm vibe upgrade --preview      # upstream commits and changed migrations; read before resolving
pnpm vibe upgrade                # switches to chore/upgrade-kit-<sha>, merges with zdiff3, never commits
git diff --name-only --diff-filter=U                            # unresolved conflicts
```

If the CLI was removed locally, run it from a kit checkout with the project as working directory. What `upgrade` does:

- adds remote `kit` from `.vibe-kit.json` and fetches the branch (or `--ref`);
- refuses when upstream modified, renamed or deleted an existing `packages/db/migrations/*.sql` (see **Escalate**);
- the first time, records the kit base as an ancestor with `merge -s ours` (tree unchanged) so git can three-way merge a project that started as a copy;
- runs `git -c merge.conflictStyle=zdiff3 merge --no-ff --no-commit --no-rerere-autoupdate`;
- drops kit-only paths `vibe create` never copies (`.planning`, `.mcp.json`, `DEVELOPMENT.md`, `AGENT-BOOTSTRAP.md`);
- stages `.vibe-kit.json` pointing at the new upstream commit.

If the branch already exists, an earlier sync was left unfinished. Inspect it, then resume or delete it deliberately. Never force-reset over it.

`zdiff3` shows the merge base inline, which tells deliberate local divergence from a line upstream simply changed. With no inline base (binary, add/add, modify/delete) read index stages: `git ls-files -u <path>`, then `git show :1:<path>` base, `:2:` ours, `:3:` theirs. For an ambiguous hunk read the commit behind it: `git log -p <old-kit-commit>..kit/main -- <path>` (old commit is `.vibe-kit.json` on `main`).

## Resolution rules

- **`AGENTS.md`** — project file generated by `vibe create`; keep local, port only new invariants from upstream's generator text in `packages/cli/src/files.ts`.
- **Env (`.env.example`)** — union: keep local values and project-only keys (`IDENTITY_PROFILE`), add new upstream keys, drop upstream-deleted keys only when the mechanism behind them is also gone.
- **Manifests (`package.json`)** — adopt upstream versions and scripts; keep project-only dependencies and scripts still in use.
- **Lockfile** — never hand-merge: resolve every manifest, `git checkout --theirs pnpm-lock.yaml`, `pnpm install`, stage the regenerated result.
- **Panels and resources registries** (`registry.ts`, `resources.ts`) — take upstream structure, keep every local import and entry, including CLI marker comments.
- **Schema (`packages/db/src/schema.ts` and siblings)** — union of upstream and local tables; then `pnpm db:generate` produces a new local migration for any upstream schema change not already shipped as a migration.
- **Migrations** — a migration that may have run is immutable. Keep local history; add upstream's new migrations, renumbering them after the last local one and fixing `meta/_journal.json`; regenerate snapshots with `pnpm db:generate` when they disagree.
- **App, API and package code** — prefer upstream's refactor, then reapply local behavior on the new structure. Never drop server-side authorization, tenant scope, validation or RLS while resolving.
- **Product copy, `apps/web`, docs** — local copy is authoritative; port only technical changes.
- **Local deletion vs upstream edit; upstream renames** — deliberate deletions stay deleted; follow renames, carrying local content to the new path.

Don't bring in upstream features that conflict with documented product scope.

## Verify

```bash
pnpm install --frozen-lockfile && pnpm check-types && pnpm lint && pnpm test && pnpm build
pnpm db:migrate   # against a disposable/dev database only
```

Green checks are necessary, not sufficient. Compare endpoints per conflicted file and overall:

```bash
git diff main..HEAD -- <path>       # upstream mechanism plus forced adaptations
git diff kit/main..HEAD -- <path>   # the project's divergence as it now stands
```

Every difference must be explainable as upstream mechanism adopted or local intent kept. Then confirm:

- no leftover conflict markers: `git diff --check main..HEAD`
- no kit placeholder copy or kit-only files (`.planning/`) in the tree
- no local panel, resource, env key or migration silently dropped
- `AGENTS.md` invariants still hold
- nothing unexpected in auto-merged files: `git diff main..HEAD --stat`

## Land

Commit `chore: upgrade kit to <short-sha>` with notable resolutions in the body. Then:

```bash
git switch main && git merge --ff-only <branch> && git branch -d <branch>
```

If `--ff-only` is refused, `main` advanced meanwhile: merge `main` into the branch and re-verify.

## Escalate

Stop and report (file, upstream intent, local intent, open choice) instead of guessing when upstream modifies a migration that may have run or changes live-data semantics, ships a feature against documented product scope, or when keeping both mechanism and local behavior is genuinely ambiguous.
