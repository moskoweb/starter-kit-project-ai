# Webhook integration

Inbound endpoint: `POST /api/webhooks/inbound/<endpointId>`. Configure one endpoint with `WEBHOOK_INBOUND_ENDPOINT_ID` (UUID) and `WEBHOOK_INBOUND_SECRET`. The endpoint remains unavailable (404) until both are valid. Never accept tenant or recipient identity from the request body.

Request limit is 256 KiB, checked while reading raw bytes before JSON parsing. Signature headers: `x-webhook-timestamp` and `x-webhook-signature: sha256=<hex>`; timestamps allow five minutes. Accepts signed envelopes `{ id, event, createdAt, data }` (no other keys) with UUID `id` and `event` matching the event name pattern (`/^[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*)+$/`, max 100). The kit only verifies the signature and inserts an idempotent `webhook_receipts` row: new receipt or identical replay returns 200; same ID with different raw body returns 409.

Processing is project-specific and intentionally not shipped. Hook point: consume `webhook_receipts` from your own code (e.g. a job that reads unprocessed receipts), validate `data` per event with Zod, resolve the acting user/tenant from trusted configuration (never the body), re-authorize, and commit your effect plus an idempotency marker atomically.

Outbound delivery uses deployment configuration, not persisted secrets: `WEBHOOK_OUTBOUND_URL`, `WEBHOOK_OUTBOUND_SECRET`, and comma-separated `WEBHOOK_OUTBOUND_ALLOWED_HOSTS`. HTTPS, exact host allowlist, public DNS, and pinned DNS required. `createDelivery(tx, context, eventId, event, payload)` persists pending delivery in caller transaction (same transaction as `enqueueEvent`); `event` must match the event name pattern, which is also the outbound allowlist. `relayWebhookDeliveries(boss)` sends due records transactionally through pg-boss and marks them queued; owner calls it in relay loop and registers `webhookHandler`. Handler is idempotent for terminal statuses. Retry delay doubles from 30 seconds, caps at 24 hours, and stops after five attempts. `listDeliveries` and `retryDelivery` require authorized tenant transaction.

DB schema is declared in `packages/db/src/webhook-schema.ts`; migration generation/application and worker registration are explicit deployment-owner operations. Secrets are environment references and never stored in DB.
