# Resource data API

Server-only query exports in `apps/app/src/lib/resources/queries.ts`: `listProjects(identifier, options)`, `getProject(identifier, id)`, `listTasks(identifier, options)`, `getTask(identifier, id)`. Lists return `{ items, total, page, pageSize }`, page size 20. Supported sort keys are allowlisted by resource; search matches project name or task title. `identifier` is `null` for personal data or explicit organization slug/UUID.

Server actions in `actions.ts`: `createProject(identifier, {name, description?})`, `updateProject(identifier, id, {name?, description?})`, `deleteProject(identifier, id)`, `bulkDeleteProjects(identifier, {ids})`, `createTask(identifier, {projectId, title})`, `updateTask(identifier, id, {title})`, `deleteTask(identifier, id)`, `bulkDeleteTasks(identifier, {ids})`. Return `{ok:true,data}` or `{ok:false,error}`. Bulk delete accepts 1–100 unique IDs; if any item is missing or outside authorized scope, action rejects whole request without deleting subset. Task schema has no status. Validation schemas live in `validation.ts`; app runtime requires `zod` and `@vibe/events` dependencies. Every operation authenticates from current Next headers and enforces tenant/RLS scope; owner and organization IDs are never accepted from input. Project-created event insert shares project transaction and runs only when `JOBS_ENABLED=true`.
